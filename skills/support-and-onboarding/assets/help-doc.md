# Help Doc — fill-in template

Copy one of these per recurring question. A good help doc **deflects the ticket**:
the customer finds the answer themselves and never emails you. Write the title the
way a confused person would search it, put the direct answer at the very top, and
keep it short.

Minimum viable doc: a searchable title, a one-line answer, a numbered how-to, a
screenshot or two, and one link onward. A doc that does not answer the question
in the first three lines is not helping.

Rules: write docs from **real tickets**, not imagination. Link them from the
matching macro. Re-check quarterly — a stale doc is a confident wrong answer, and
that is worse than no doc at all.

Placeholders: `[PRODUCT]`, `[ACTION]`, `[STEP]`, `[FEATURE]`, `[LINK]`.

---

# How to [ACTION] in [PRODUCT]

_[One line: the direct answer. If a customer reads only this, they are unblocked.]_

## What this is for

[One or two sentences on when someone needs this, in the customer's words.]

## Steps

1. [First step — start from where they actually are, e.g. "Open your dashboard."]
2. [Second step.]
3. [Third step — end at the observable result.]
4. [Save / confirm / you're done.]

## Screenshot

[Embed an annotated screenshot of the exact screen. Annotate the button they
should click — do not leave them hunting.]

## Common problems

- **"[Likely error or confusion]"** — [the one-line fix].
- **"I don't see [FEATURE]"** — [the most common reason, usually a plan or a
  permission, and where to check it].

## Related

- [Link to the adjacent doc that gets asked next.]

---

## Writing notes (delete before publishing)

- **Search the title.** If you wouldn't type this exact phrase when stuck, the
  title is wrong.
- **Answer first, explain later.** The answer goes above the fold.
- **One question per doc.** Two questions means two docs; a doc that answers
  everything answers nothing.
- **No jargon.** Use the words your customers use in tickets, not your internal
  names for things.
- **Update on change.** When the flow changes, the doc changes the same day, or
  it becomes a wrong answer you keep giving.
- **Every doc has a job.** If a doc doesn't reduce a recurring ticket, it is not
  earning its maintenance. Retire it.
